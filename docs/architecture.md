# 架构

## 用途

记录两类内容：
1. **重要决定**：方法和设计上已经定下的选择，用 ADR 格式（决定 / 理由 / 放弃的替代方案）。新决定追加在末尾，编号递增；推翻旧决定时新写一条，并在旧条目标"已被 ADR-xxx 取代"。
2. **项目结构**：代码和数据的组织方式。

研究问题见 [prd.md](prd.md)；技术栈见 [tech_stacks.md](tech_stacks.md)；计划见 [roadmap.md](roadmap.md)。

> 标注约定见 [prd.md](prd.md) 开头。

## 重要决定

以下 ADR 全部来自 [项目总览](../misc/项目总览-用户模拟器真实性.md) 和 [任务规格](../misc/任务规格-试跑.md)，状态均为"已采纳"，日期为 2026-10-25（录入日）。

### ADR-001 逐轮重放为主，自由对话模拟为补充

- **决定：** 保持真实对话前 t−1 轮不变（包括真实客服的发言），只让模拟器生成第 t 轮。不输入第 t 轮及之后的任何内容。自由对话模拟只用于"未解决就离开"这类整段对话层面的行为，放在第一阶段后半段。
- **理由：** 客服一侧完全相同，差异只来自模拟器。真实日志中用户面对的是人工客服；如果让模拟器和我们的 agent 自由对话，差异无法归因。
- **放弃的替代方案：** 以自由对话模拟为主。

### ADR-002 配对比较为主，整体分布比较为辅

- **决定：** 主要比较同一上下文下，真人做了某个行为时，模拟器有没有做。整体分布比较作辅助。
- **理由（推断）：** 项目总览未单独说明。与 ADR-001 同源：同一上下文下逐条对比，差异可归因于模拟器。
- **放弃的替代方案：** 以整体分布比较为主。

### ADR-003 能用规则就用规则；判断模型与模拟器分离

- **决定：** 能用规则统计的行为用规则。需要模型判断的行为，判断模型不能和模拟器是同一个。人工抽查约 50 条，确认准确率。正式实验中关键行为使用经过验证的分类器。
- **理由：** 同一模型做判断会偏向自己的输出风格。关键词规则会误判，需要抽查和验证。
- **放弃的替代方案：** 用模拟器本身（Spark）兼任判断模型（见文末附注 1）。

### ADR-004 第二阶段只用 WildChat 英文子集

- **决定：** 第二阶段只用 WildChat 英文子集，并按清洗规则处理（[tech_stacks.md](tech_stacks.md) 4.2）。
- **理由：** WildChat 收集期间，中国大陆用户大多通过代理或 VPN 访问 ChatGPT，共享出口 IP 很常见。用 hashed_ip 串联"同一用户"在中文子集上不可靠。
- **放弃的替代方案：** 中文子集，或中英双语对比（见文末附注 2）。

### ADR-005 评估管线设计为可复用

- **决定：** 从第一天起把评估管线写成可复用的。
- **理由：** 第一阶段（中文任务型对话）和第二阶段（英文通用聊天）领域和语言都不同，结论不能直接叠加。三个阶段共享的是评估方法。
- **放弃的替代方案：** 每个阶段单独写一次性脚本。
- **与试跑的关系：** 试跑不过度工程化（[tech_stacks.md](tech_stacks.md) 第 1 节）。可复用的具体程度在试跑后确定（见下方项目结构）。

### ADR-006 Spark 2.6 为主力，另加小样本多模型对比

- **决定：** Spark 2.6 作主力模拟器。另用一两个低价模型做小样本对比。试跑阶段只用 Spark，失败时不静默换模型。
- **理由：** Spark 有 10 亿 token 免费额度。只用 Spark 的结论没有普遍性，需要确认发现不是 Spark 特有的。
- **放弃的替代方案：** 只用单一模型。
- 对比模型和 MIMESIS 的选择见 [roadmap.md](roadmap.md) D3、D4。

### ADR-007 修正方法首选原话片段约束

- **决定：** 用同类真实用户的原话片段约束模拟器，与无约束基线对比。
- **理由（未核实）：** RealUserSim 的消融实验显示，去掉原话示例会让保真度下降约 8 个百分点；去掉人口统计标签几乎没有影响。另据 Gemini 报告，Sim2Real Gap 论文中用手写 Persona 规则约束模拟器反而使指标变差。
- **放弃的替代方案：** 人口统计标签画像；手写抽象行为规则；训练专用模拟器（MIMESIS 路线，超出资源约束）。

### ADR-008 第二阶段合并两个问题，先个体后时间

- **决定：** 原来的"跨会话演化"和"个人历史"合并为第二阶段。先做个体维度（简单 A/B 对比），再做时间维度。
- **理由：** 两个问题用同一份数据、同一套管线。
- **放弃的替代方案：** 两个问题各自成为独立阶段。

### ADR-009 用户诉求摘要删去结果部分

- **决定：** CSDS 用户诉求摘要作为模拟器任务目标时，删去其中的对话结果（例如"最终退款成功"），只保留诉求。删除规则写入 notes。
- **理由：** 否则模拟器会提前知道结局。
- **放弃的替代方案：** 直接使用原始摘要。

### ADR-010 用户轮次的定义

- **决定：** 两次客服发言之间，用户发出的全部消息合并为一个用户轮次；连发多条时用换行符分隔保留。
- **理由：** 来自任务规格第 3 步，作为逐轮重放和规则统计的基本单位。
- **放弃的替代方案：** 每条消息单独算一轮（任务规格未说明放弃理由）。
- **注意：** 实际数据中连发消息如何记录，需在试跑第 1 步确认后复核本决定。

### ADR-011 升级行为用人工客服场景的替代行为

- **决定：** 不测"要求转人工"，改测要求主管、威胁投诉或差评、重复追问、未解决就离开。
- **理由：** CSDS、MobileCS、ECD 中用户面对的都是人工客服，"要求转人工"不存在。行为清单见 [prd.md](prd.md) 4.2。
- **放弃的替代方案：** 测"要求转人工"（见文末附注 3）。

### ADR-012 Spark 默认关闭思考模式

- **决定：** 调用 `spark-x2.6` 时传 `"thinking": {"type": "disabled"}`。只有任务确实需要推理时才开启，并在输出中注明。
- **理由：** 用户决定（2026-10-25）。思考模式默认开启，速度慢、token 多（见 [tech_stacks.md](tech_stacks.md) 第 3 节实测）。
- **放弃的替代方案：** 官方默认（思考开启）；`auto`。
- **与任务规格的关系：** 任务规格要求"使用官方默认参数"，仅 thinking 一项按本 ADR 覆盖；temperature 仍用默认值。
- **扩展（2026-10-25）：** 所有模拟器都关闭推理，否则模型之间不可比。`deepseek-v4.1-flash` 同样传 `"thinking": {"type": "disabled"}`。判断模型（Gemini）关不掉，不受此限。

### ADR-013 内容审核拒绝的轮次剔除，不停止

- **决定：** Spark 返回 HTTP 400 且错误码 `10013`（内容审核拒绝）时，不重试，该轮标记为 `moderated`。真人和模拟器两侧都从配对指标中剔除。报告中写明被拒轮次的数量、比例和所属对话。其他错误仍按停止条件处理。
- **理由：** Claude 决定（2026-10-25，用户授权自主推进）。首次扩大样本中，对话 3757 的历史含成人用品商品名，被确定性拒绝，导致整批停止。这不是可重试的故障。
- **放弃的替代方案：** 停止整批（首版做法）；剔除整段对话（丢掉同段内正常的轮次）；改写数据绕过审核（改变真实数据）。
- **局限：** 被拒内容集中在特定商品类别，剔除会带来少量选择偏差，需在报告中说明。

### ADR-014 送入模拟器的文本去掉分词空格

- **决定：** CSDS 原文带分词空格（如"有 什么 问题"）。送入模拟器的对话历史和任务目标，去掉中文字符之间的空格；英文、数字之间的空格保留。对照表保存原文，指标计算本来就去空白。
- **理由：** Claude 决定（2026-10-25）。分词是数据集加工的产物，真人当时输入的文本没有这些空格。保留会让模拟器看到不自然的输入，可能影响它的风格，构成混杂。
- **放弃的替代方案：** 原样输入（首版做法，结果保存在 `outputs/archive/v1_segmented/`，可用于对比敏感性）。

### ADR-015 修正摘要清洗规则后全部重跑

- **决定：** 首版删除规则有漏删（如 2403、10197）和过删（如 10049）。改进规则，并对所有被抽中对话的摘要逐条人工式核对，规则不对的用逐条覆盖表修正。任务目标变化后，相关轮次全部重新生成。
- **理由：** 任务规格"每轮只生成一次"是为了不挑选结果，不禁止因输入被修正而重跑。
- **放弃的替代方案：** 保留已有生成、只在报告中注明漏删。

### ADR-016 核心结论：客服回应之后的"反应方式"（定义与预先登记的判定规则）

- **决定（用户 2026-10-26）：** 第一阶段以"反应方式"为核心结论。假设：客服回应之后，真人往往就此结束这一话题，模拟器则继续提出要求，并把情绪说出来。
- **两个指标分开测，用 2×2 报告：**
  - **话题走向**（每个用户轮次三选一）：
    - `close` 结束话题：接受、确认或致谢，且不在同一问题上继续追问；或转去问与原问题无关的新问题。
    - `continue` 继续要求：在同一问题上追问、加码、提出新的要求或替代办法、表达不接受。
    - `unclear` 无法判断：信息不足，如只发订单号或链接，或是对客服提问的直接作答。
  - **情绪表达**（是/否）：明确说出不满、着急、失望等负面情绪或态度。只有感叹号不算。
- **判断：** 用判断模型 `gemini-3.8-flash`（ADR-003：不能与模拟器相同）。先由 Codex 人工式标注标准集：开发集约 100 轮，用于调 prompt；测试集约 200 轮，只在最后评估一次。验收门槛（Claude 设定，可由用户调整）：测试集上话题走向的 Cohen's κ ≥ 0.70 且准确率 ≥ 85%；情绪表达的 κ ≥ 0.70。达不到就不上量，回报用户。
- **对照组与限定规则（先于看数据登记）：**
  - 分组：客服负面回应之后（`usersim/behaviors.py` 的现有规则）vs 非负面之后。
  - 每组算"模拟器 − 真人"的差距；再算交互项 = 负面组差距 − 非负面组差距。区间都用按对话的配对 bootstrap 95%。
  - 判定：以"话题走向 = continue 的比例"为主指标。交互项区间不含零，且负面组差距的绝对值更大，就把核心结论限定在"被拒之后"；否则用"客服回应之后"的普遍定义。情绪表达指标同样计算并报告，但不参与这一判定。
- **理由：** 混杂检查后反应方式失真仍在（`outputs/decision_ab/report.md`）：允许让步只缩小约三分之一的差距，DeepSeek 偏得更远。现有指标（短句、未解决接受、重复追问）只是近似，需要直接测"结束还是继续"。把判定规则先登记再看数据，是为了避免看了结果再挑定义。
- **放弃的替代方案：** 两个维度合成一个指标（难以解释）；只用关键词规则（无法判断"是否同一话题"）；先看结果再决定是否限定在"被拒之后"。
- **局限：** 逐轮重放只比较真人确实回复了的轮次。真人一句话不说、直接离开的情况，这个设计看不到，要靠自由对话模拟（ADR-001 的补充部分）。

### ADR-017 全量基线中未人工核对的摘要只用规则清洗

- **决定：** 全量 CSDS（9,910 段）基线中，没有人工核对记录的对话，只用规则清洗任务目标；已核对的 520 段仍用覆盖表。每段在 `summary_audit.json` 中标记是否核对过，报告未核对的段数。
- **理由：** Claude 决定（2026-10-26）。逐段人工核对 9,910 段不现实。已核对的 520 段里，改进后的规则只有 3 段需要人工修正（约 0.6%），误差可接受。
- **放弃的替代方案：** 全部人工核对；用模型清洗摘要（会引入新的模型偏差，且 Spark 不能兼任）。
- **局限：** 约 0.6% 的段落可能残留结果信息或误删诉求，会在全量报告中注明。

## 项目结构

试跑后（2026-10-25）的结构。数据集适配和指标是分开的，第一阶段换数据集或第二阶段换 WildChat 时，只需新增一个适配模块（ADR-005）。

```
usersim/            可复用的核心库
  csds.py           CSDS 适配：读取、合并用户轮次（ADR-010）、摘要清洗（ADR-009/015）、抽样
  replay.py         逐轮重放的 prompt：只取第 t 轮之前的真实前缀，去分词空格（ADR-001/014）
  spark.py          Spark 客户端：并发、退避重试、10013 记为 moderated（ADR-012/013），逐请求记 token
  metrics.py        规则指标（关键词在 config/keywords.json）
  report.py         汇总表和 report.md
  anchors.py        修正方法：真实原话示例池与抽取（ADR-007，探索性）
config/
  keywords.json           关键词规则（已经过审查修订）
  summary_overrides.json  逐段摘要清洗覆盖
  summary_reviews.json    逐段摘要核对记录
scripts/
  run_pilot.py            入口：--n --seed --out；支持断点续跑和 --refresh-only（不调 API，只重算）
  run_correction_pilot.py 修正方法预跑（C1 随机原话 / C2 同类原话）
  check_outputs.py, check_correction_pilot.py, audit_leakage.py   输出校验与泄漏审计
  build_d1_brief.py       D1 证据材料（配对 bootstrap）
  其余                    审查与敏感性分析的一次性脚本
tests/              pytest
outputs/            试跑 20 段；extended/ 500 段；correction_pilot/；archive/v1_segmented/ 首版
data/raw/           原始数据（不进 git）
```

依赖：`httpx`、`pytest`（`requirements.txt`）。虚拟环境 `.venv` 用 Python 3.12 建。
