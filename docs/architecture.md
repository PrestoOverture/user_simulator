# 架构

1. **重要决定**：方法和设计上已经定下的选择，用 ADR 格式（决定 / 理由 / 放弃的替代方案）。新决定追加在末尾，编号递增；推翻旧决定时新写一条，并在旧条目标"已被 ADR-xxx 取代"。

研究问题见 [prd.md](prd.md)；技术栈见 [tech_stacks.md](tech_stacks.md)；计划见 [roadmap.md](roadmap.md)。

## 重要决定

以下 ADR 全部来自 [项目总览](../misc/项目总览-用户模拟器真实性.md) 和 [任务规格](../misc/任务规格-试跑.md)，状态均为"已采纳"，日期为 2026-10-25（录入日）。

### ADR-001 逐轮重放为主，自由对话模拟为补充（"直接离开"的测法已由 ADR-019 修改）

- **决定：** 保持真实对话前 t−1 轮不变（包括真实客服的发言），只让模拟器生成第 t 轮。不输入第 t 轮及之后的任何内容。自由对话模拟只用于"未解决就离开"这类整段对话层面的行为，放在第一阶段后半段。
- **理由：** 客服一侧完全相同，差异只来自模拟器。真实日志中用户面对的是人工客服；如果让模拟器和我们的 agent 自由对话，差异无法归因。
- **放弃的替代方案：** 以自由对话模拟为主。

### ADR-002 配对比较为主，整体分布比较为辅

- **决定：** 主要比较同一上下文下，真人做了某个行为时，模拟器有没有做。整体分布比较作辅助。
- **理由（推断）：** 项目总览未单独说明。与 ADR-001 同源：同一上下文下逐条对比，差异可归因于模拟器。
- **放弃的替代方案：** 以整体分布比较为主。
- **补充（2026-11-11）：** 到 P2 为止，报告的主数字都是边际差距，配对一致性没有报过。必报的配对指标见 ADR-022 第 5 点。

### ADR-003 能用规则就用规则；判断模型与模拟器分离（判断模型部分已被 ADR-018 部分取代）

- **决定：** 能用规则统计的行为用规则。需要模型判断的行为，判断模型不能和模拟器是同一个。人工抽查约 50 条，确认准确率。正式实验中关键行为使用经过验证的分类器。
- **理由：** 同一模型做判断会偏向自己的输出风格。关键词规则会误判，需要抽查和验证。
- **放弃的替代方案：** 用模拟器本身（Spark）兼任判断模型（见文末附注 1）。

### ADR-004 第二阶段只用 WildChat 英文子集

- **决定：** 第二阶段只用 WildChat 英文子集，并按清洗规则处理（[tech_stacks.md](tech_stacks.md) 4.2）。
- **理由：** WildChat 收集期间，中国大陆用户大多通过代理或 VPN 访问 ChatGPT，共享出口 IP 很常见。用 hashed_ip 串联"同一用户"在中文子集上不可靠。
- **放弃的替代方案：** 中文子集，或中英双语对比（见文末附注 2）。

### ADR-005 评估管线设计为可复用

- **决定：** 从第一天起把评估管线写成可复用的。
- **理由：** 第一阶段（中文任务型对话）和第二阶段（英文通用聊天）领域和语言都不同，结论不能直接叠加。三个阶段共享的是评估方法。
- **放弃的替代方案：** 每个阶段单独写一次性脚本。
- **与试跑的关系：** 试跑不过度工程化（[tech_stacks.md](tech_stacks.md) 第 1 节）。可复用的具体程度在试跑后确定（见下方项目结构）。

### ADR-006 Spark 2.6 为主力，另加小样本多模型对比

- **决定：** Spark 2.6 作主力模拟器。另用一两个低价模型做小样本对比。试跑阶段只用 Spark，失败时不静默换模型。
- **理由：** Spark 有 10 亿 token 免费额度。只用 Spark 的结论没有普遍性，需要确认发现不是 Spark 特有的。
- **放弃的替代方案：** 只用单一模型。
- 对比模型和 MIMESIS 的选择见 [roadmap.md](roadmap.md) D3、D4。

### ADR-007 修正方法首选原话片段约束

- **决定：** 用同类真实用户的原话片段约束模拟器，与无约束基线对比。
- **理由（未核实）：** RealUserSim 的消融实验显示，去掉原话示例会让保真度下降约 8 个百分点；去掉人口统计标签几乎没有影响。另据 Gemini 报告，Sim2Real Gap 论文中用手写 Persona 规则约束模拟器反而使指标变差。
- **放弃的替代方案：** 人口统计标签画像；手写抽象行为规则；训练专用模拟器（MIMESIS 路线，超出资源约束）。

### ADR-008 第二阶段合并两个问题，先个体后时间

- **决定：** 原来的"跨会话演化"和"个人历史"合并为第二阶段。先做个体维度（简单 A/B 对比），再做时间维度。
- **理由：** 两个问题用同一份数据、同一套管线。
- **放弃的替代方案：** 两个问题各自成为独立阶段。

### ADR-009 用户诉求摘要删去结果部分

- **决定：** CSDS 用户诉求摘要作为模拟器任务目标时，删去其中的对话结果（例如"最终退款成功"），只保留诉求。删除规则写入 notes。
- **理由：** 否则模拟器会提前知道结局。
- **放弃的替代方案：** 直接使用原始摘要。

### ADR-010 用户轮次的定义

- **决定：** 两次客服发言之间，用户发出的全部消息合并为一个用户轮次；连发多条时用换行符分隔保留。
- **理由：** 来自任务规格第 3 步，作为逐轮重放和规则统计的基本单位。
- **放弃的替代方案：** 每条消息单独算一轮（任务规格未说明放弃理由）。
- **注意：** 实际数据中连发消息如何记录，需在试跑第 1 步确认后复核本决定。

### ADR-011 升级行为用人工客服场景的替代行为

- **决定：** 不测"要求转人工"，改测要求主管、威胁投诉或差评、重复追问、未解决就离开。
- **理由：** CSDS、MobileCS、ECD 中用户面对的都是人工客服，"要求转人工"不存在。行为清单见 [prd.md](prd.md) 4.2。
- **放弃的替代方案：** 测"要求转人工"（见文末附注 3）。

### ADR-012 Spark 默认关闭思考模式

- **决定：** 调用 `spark-x2.6` 时传 `"thinking": {"type": "disabled"}`。只有任务确实需要推理时才开启，并在输出中注明。
- **理由：** 用户决定（2026-10-25）。思考模式默认开启，速度慢、token 多（见 [tech_stacks.md](tech_stacks.md) 第 3 节实测）。
- **放弃的替代方案：** 官方默认（思考开启）；`auto`。
- **与任务规格的关系：** 任务规格要求"使用官方默认参数"，仅 thinking 一项按本 ADR 覆盖；temperature 仍用默认值。
- **扩展（2026-10-25）：** 所有模拟器都关闭推理，否则模型之间不可比。`deepseek-v4.1-flash` 同样传 `"thinking": {"type": "disabled"}`；自 2026-10-27 起网关不再理会它，须同时传 `"reasoning_effort": "none"`（[tech_stacks.md](tech_stacks.md) 第 2 节）。判断模型（Gemini）关不掉，不受此限。
- **例外（2026-10-28）：** Spark 当判断器时开启思考（开发集上 κ 更高），见 ADR-018。

### ADR-013 内容审核拒绝的轮次剔除，不停止

- **决定：** Spark 返回 HTTP 400 且错误码 `10013`（内容审核拒绝）时，不重试，该轮标记为 `moderated`。真人和模拟器两侧都从配对指标中剔除。报告中写明被拒轮次的数量、比例和所属对话。其他错误仍按停止条件处理。
- **理由：** Claude 决定（2026-10-25，用户授权自主推进）。首次扩大样本中，对话 3757 的历史含成人用品商品名，被确定性拒绝，导致整批停止。这不是可重试的故障。
- **放弃的替代方案：** 停止整批（首版做法）；剔除整段对话（丢掉同段内正常的轮次）；改写数据绕过审核（改变真实数据）。
- **局限：** 被拒内容集中在特定商品类别，剔除会带来少量选择偏差，需在报告中说明。

### ADR-014 送入模拟器的文本去掉分词空格

- **决定：** CSDS 原文带分词空格（如"有 什么 问题"）。送入模拟器的对话历史和任务目标，去掉中文字符之间的空格；英文、数字之间的空格保留。对照表保存原文，指标计算本来就去空白。
- **理由：** Claude 决定（2026-10-25）。分词是数据集加工的产物，真人当时输入的文本没有这些空格。保留会让模拟器看到不自然的输入，可能影响它的风格，构成混杂。
- **放弃的替代方案：** 原样输入（首版做法，结果保存在 `outputs/archive/v1_segmented/`，可用于对比敏感性）。

### ADR-015 修正摘要清洗规则后全部重跑

- **决定：** 首版删除规则有漏删（如 2403、10197）和过删（如 10049）。改进规则，并对所有被抽中对话的摘要逐条人工式核对，规则不对的用逐条覆盖表修正。任务目标变化后，相关轮次全部重新生成。
- **理由：** 任务规格"每轮只生成一次"是为了不挑选结果，不禁止因输入被修正而重跑。
- **放弃的替代方案：** 保留已有生成、只在报告中注明漏删。

### ADR-016 核心结论：客服回应之后的"反应方式"（定义与预先登记的判定规则；结论措辞已由 ADR-022 修订）

- **决定（用户 2026-10-26）：** 第一阶段以"反应方式"为核心结论。假设：客服回应之后，真人往往就此结束这一话题，模拟器则继续提出要求，并把情绪说出来。
- **两个指标分开测，用 2×2 报告：**
  - **话题走向**（每个用户轮次三选一）：
    - `close` 结束话题：接受、确认或致谢，且不在同一问题上继续追问；或转去问与原问题无关的新问题。
    - `continue` 继续要求：在同一问题上追问、加码、提出新的要求或替代办法、表达不接受。
    - `unclear` 无法判断：信息不足，如只发订单号或链接，或是对客服提问的直接作答。
  - **情绪表达**（是/否）：明确说出不满、着急、失望等负面情绪或态度。只有感叹号不算。
- **判断：** 用判断模型 `gemini-3.8-flash`（ADR-003：不能与模拟器相同；2026-10-28 起新实验按 ADR-018）。先由 Codex 人工式标注标准集：开发集约 100 轮，用于调 prompt；测试集约 200 轮，只在最后评估一次。验收门槛（Claude 设定，可由用户调整）：测试集上话题走向的 Cohen's κ ≥ 0.70 且准确率 ≥ 85%；情绪表达的 κ ≥ 0.70。达不到就不上量，回报用户。
- **对照组与限定规则（先于看数据登记）：**
  - 分组：客服负面回应之后（`usersim/behaviors.py` 的现有规则）vs 非负面之后。
  - 每组算"模拟器 − 真人"的差距；再算交互项 = 负面组差距 − 非负面组差距。区间都用按对话的配对 bootstrap 95%。
  - 判定：以"话题走向 = continue 的比例"为主指标。交互项区间不含零，且负面组差距的绝对值更大，就把核心结论限定在"被拒之后"；否则用"客服回应之后"的普遍定义。情绪表达指标同样计算并报告，但不参与这一判定。
- **理由：** 混杂检查后反应方式失真仍在（`outputs/decision_ab/report.md`）：允许让步只缩小约三分之一的差距，DeepSeek 偏得更远。现有指标（短句、未解决接受、重复追问）只是近似，需要直接测"结束还是继续"。把判定规则先登记再看数据，是为了避免看了结果再挑定义。
- **放弃的替代方案：** 两个维度合成一个指标（难以解释）；只用关键词规则（无法判断"是否同一话题"）；先看结果再决定是否限定在"被拒之后"。
- **局限：** 逐轮重放只比较真人确实回复了的轮次。真人一句话不说、直接离开的情况，这个设计看不到，要靠自由对话模拟（ADR-001 的补充部分）。
- **判定结果（2026-10-26）：** 用普遍定义。continue 交互项 −2.3 个百分点 [−6.2, +1.9]，区间含零。详见 `outputs/reaction/full/report.md`。
- **跨模型复核（2026-10-28）：** DeepSeek 上同样用普遍定义，交互项 +3.8 [−0.1, +7.8]。详见 `outputs/reaction/deepseek/report.md`。

### ADR-017 全量基线中未人工核对的摘要只用规则清洗

- **决定：** 全量 CSDS（9,910 段）基线中，没有人工核对记录的对话，只用规则清洗任务目标；已核对的 520 段仍用覆盖表。每段在 `summary_audit.json` 中标记是否核对过，报告未核对的段数。
- **理由：** Claude 决定（2026-10-26）。逐段人工核对 9,910 段不现实。已核对的 520 段里，改进后的规则只有 3 段需要人工修正（约 0.6%），误差可接受。
- **放弃的替代方案：** 全部人工核对；用模型清洗摘要（会引入新的模型偏差，且 Spark 不能兼任）。
- **局限：** 约 0.6% 的段落可能残留结果信息或误删诉求，会在全量报告中注明。

### ADR-018 Spark 判全量 + Gemini 抽样校正（PPI）（部分取代 ADR-003）

- **决定（用户 2026-10-28）：** ADR-016 两个指标的判断改为两步。第一步，Spark（`spark-x2.6`，thinking enabled，冻结判断 prompt）判断全部轮次。第二步，Gemini（`gemini-3.8-flash`）只判随机抽取的 100 段对话，用 PPI 校正 Spark 的偏差。正式结论以校正后的估计和按对话 bootstrap 的区间为准。抽样对话在发请求前登记，固定种子。
- **这是看过结果后的决定。** 合同 C 预先登记了两条采纳标准，n=100 时：(1) 所有条件的区间覆盖率 ≥ 90%；(2) 区间宽度比只用 Gemini 窄 ≥ 20%。结果：(1) 全部达标（91.4–97.4%）；(2) 有一格没过——reaction/full 非负面组的情绪指标只窄了 16.7%，其余 17–38%。按预先登记的规则，判定为"未达标"。用户看过结果后决定仍然采纳，理由是：有效性全部达标，只是效率在一格上差了一点。论文中必须如实写明这一点。证据见 `outputs/spark_judge_validation/report.md`。
- **理由：** 付费的 sandbox token 能省则省；Spark 免费（用户 2026-10-27）。ADR-003 担心的是"模拟器自己判自己会偏"。PPI 下，这种偏差会被 Gemini 样本在每个条件内估计出来并扣掉，最终估计的无偏性来自 Gemini。测试集上也没有看到 Spark 偏袒自己输出的迹象。
- **范围：** ADR-003 的"判断模型不能和模拟器是同一个"，在 PPI 框架下放宽为：Spark 可以作为辅助判断器，但每个条件都必须有独立的 Gemini 校正样本。只用 Spark 判断的数字只能作为探索性结果。已经用 Gemini 全量判断过的结果（ADR-016 分组测量、P2 v2、DeepSeek 分组测量）保持不变。
- **放弃的替代方案：** 守住预先登记的标准，继续用 Gemini 全量判断（每个实验约 7–10 美元）；只用 Spark 判断（偏差无法校正）。
- **局限：** 校正样本小（100 段），区间比 Gemini 全量宽；分组细、轮次少的格子效率最低。

### ADR-019 "直接离开"用带离开选项的逐轮重放测量（修改 ADR-001 的补充部分）

- **决定（Claude 2026-10-28，用户同意先做这一项）：** 不搭建 AI 客服做自由对话，改用逐轮重放。在 prompt 中加一个固定的"离开"选项（输出 [离开]），比较两类点：真实离开点，即对话以客服消息结束、用户之后再没发言；以及配对的继续点。按规则统计，不用判断模型，只用 Spark。
- **理由：** 自由对话需要 AI 扮演客服，而真实日志中的用户面对的是人工客服。客服一侧不同，差异就无法归因，这正是 ADR-001 要避免的问题。离开选项保留了配对比较。
- **放弃的替代方案：** Spark 扮演客服的自由对话（客服一侧有混杂）。
- **局限：** 显式选项对模拟器有利，真人离开往往只是不再回复。这个方法只能测"在真人离开的地方，模拟器愿不愿意离开"，测不到整段对话中途放弃。

### ADR-020 暂不做模型训练（D9）（已被 ADR-021 取代）

- **决定（用户 2026-10-28）：** 暂不把 LoRA 等模型训练纳入项目。只有在不得不走训练这条路时才重新考虑。[prd.md](prd.md) 5.2 不变。
- **理由：** 用户认为成本太高（估算见 [tech_stacks.md](tech_stacks.md) 2.1）。
- **放弃的替代方案：** 用 Qwen3.5-4B（可选 9B）做 LoRA，与未训练的基座对比。
- **影响：** P2 只保留免训练修正的结果，第一阶段的结论是"免训练的提示词修正压不住反应方式的失真"。下一步进入 P3。

### ADR-021 用 Kaggle 免费 GPU 做小规模 LoRA 修正（D9，取代 ADR-020；评估口径已由 ADR-023 修订）

- **决定（用户 2026-11-09）：** 把小规模 LoRA 微调纳入第一阶段，作为修正方法之一。模型 `Qwen/Qwen3.5-4B`，Kaggle T4，fp16 LoRA；9B 视 4B 结果再定。训练集从 CSDS train 中每段对话抽 1 个用户轮次（排除 500 段评估对话），目标文本额外去掉汉字与标点之间的分词空格；输入 prompt 与 `usersim/replay.py` 完全一致。评估与免训练修正同口径：同一批 500 段，ADR-016 两个指标，按 ADR-018 判断，并与未训练的 Qwen 基座对比。
- **理由：** 免训练修正都压不住"继续要求"的差距（ADR-020 的背景）；Kaggle 每周 30 小时免费 GPU 消除了成本顾虑。小试（[history.md](history.md) 2026-11-09）显示 4B 能在 T4 上跑，但全量逐轮训练约 49 小时，超出额度，所以抽样。
- **放弃的替代方案：** 维持不训练（ADR-020）；全量逐轮训练（超出额度）；付费 GPU（AutoDL）。
- **影响：** [prd.md](prd.md) 5.2 加了例外。Spark 无法微调，所以比较的是"Qwen 基座 vs Qwen+LoRA"，与 Spark 基线的差距只作参照。

### ADR-022 核心结论的措辞与必报指标（修订 ADR-016 的解释；定义、标签、判定规则不变）

- **决定（Claude 2026-11-11 复盘提出，用户要求写入）：**
  1. **核心结论改写为：** 客服回应之后，真人每轮只走一小步（应答、给信息或收尾），模拟器每轮都推进诉求。不再写"真人往往就此结束这一话题"。continue 差距的数字不变。
  2. **`close` 不等于"结束话题"。** 它包含"好的""嗯"这类应答。报告中称为"应答或收尾"。
  3. **分两段报告。** 对话中段：差距主要来自 `unclear`（真人只答问题或给信息，模拟器在回答之外加要求）。对话末尾：模拟器不会收尾。
  4. **修正结论写成"试过的几类免训练修正修不动"。** 不写"不能靠提示词修正"。oracle 的"只缩小 44%"要写明局限：指令放在 prompt 最前面；`unclear` 遵守率只有 49%。decision 组的目标只按"负面 / 非负面"两组的边际分布抽取，不看具体情境，也要写明。
  5. **配对一致性为必报指标（落实 ADR-002）。** 每个模拟器条件都报"模拟器与真人话题标签"的一致率和 Cohen's κ，与边际差距并列。一种修正要算"有效"，边际差距要缩小，κ 也不能下降。
  6. **去混杂结论收窄。** 在 [roadmap.md](roadmap.md) R2 完成前，"失真不是任务目标造成的"只能写成"在规则指标、客服负面回应之后成立"。
- **理由（500 段、4,300 轮的 Gemini 判断，Claude 离线计算，**待 R0 脚本复现**）：**
  - 真人被判 `close` 的 1,215 轮中：35% 是对话最后一轮；22% 的下一轮是 `continue`；31% 之后还会出现 `continue`。
  - 按位置：中段（2,708 轮）continue 差距 +25.1 个百分点，其中真人 `unclear` 31% 对 Spark 13%，`close` 13% 对 6%。最后一轮差距 +36.1，真人 `close` 84% 对 Spark 49%。差距在各位置都存在。
  - 配对：Spark 基线与真人的一致率 60%，κ 0.30。P2 v2 三种修正的 κ 为 0.26–0.32，没有提高。真人 `close` 时 Spark 有 62% 是 `continue`。
  - 边际比例可以被"随机多说好的"拉平，只看它不够（见 ADR-023 的 LoRA 输出）。
  - 消融 A 只用规则指标、只在负面回应之后测过，没有用 continue 指标测。
- **放弃的替代方案：** 维持原措辞（与数据不符）；改 `close` 的标签定义后全部重判（成本高，且已有结果的数字本身没错，错的是解读）。
- **影响：** [prd.md](prd.md) 4.2 已改。`paper/phase1_draft.md` 和 `README.md` 的旧措辞在 [roadmap.md](roadmap.md) R4 改，在此之前不对外引用。
- **回滚：** 见 [roadmap.md](roadmap.md) 4.4。

### ADR-023 LoRA 评估口径（修订 ADR-021 的评估部分；训练部分不变）

- **决定（Claude 2026-11-11 复盘提出，用户要求写入；阈值由 Claude 设定，可由用户调整）：**
  1. **解码：** 评估生成用 temperature 1、top_p 1、不设 top_k。基座和 LoRA 相同。2026-11-09/10 的生成（0.7 / 0.8 / 20）只作敏感性对照，不再为它花 Gemini。
  2. **规则闸门（免费，先于判断）：** 在同一批评估轮次上与真人比。纯应答率不超过真人的 1.5 倍；不重复输出占比不低于真人的 0.8 倍；空输出与触到长度上限合计不超过 2%。规则定义在 R0 脚本中冻结。没过闸门不发 Gemini 请求。
  3. **判断：** 按 ADR-018。两个主指标：continue 差距（带符号）和配对 κ（ADR-022）。κ 以 Gemini 校正样本（100 段）为准，Spark 全量的 κ 只作探索性结果。情绪指标照常报告，不参与判定。
  4. **判定（发 Gemini 请求前登记）：**
     - **有效：** continue 差距的绝对值比基座缩小至少 50%（缩小量的区间下界大于零），κ 高于基座（差值区间不含零），并过了规则闸门。
     - **过冲：** 差距区间整体小于零，且绝对值不小于 5 个百分点。不算有效。
     - 其余如实报告为部分有效或无效。
  5. **最多重训一次。** 没过闸门时，只改一处：每段对话抽 3 个不同的用户轮次（数据约 3 倍），其余超参不变。重训后不论是否过闸门，判断一次并如实报告，LoRA 路线到此结束。
- **理由：**
  - 现有 LoRA 输出比真人更集中（同一批 4,710 轮，Claude 离线计算，**待 R0 脚本复现**）：恰为"好的"10.5% 对真人 2.9%；纯应答 33.9% 对 13.7%；不重复输出占比 52% 对 79%；中位字数 6 对 10。基座 Qwen 相反：纯应答 0.2%，中位 37 字。
  - 低温加截断会把分布压向最常见的回复（**推断**，R1 验证）。按真人数据训练的模型，要按原分布采样才可比。Spark 基线用的也是默认 temperature 1。
  - 原报告只输出边际差距。LoRA 若把 continue 压到真人以下，会被读成"修好了"。
  - LoRA 有分辨力但误报高：真人是纯应答时它 76% 也是，真人不是时它 27% 是。所以要报配对指标。
  - "[订单编号]"不清洗：真人也有 0.8%，LoRA 为 2.2%。
- **放弃的替代方案：** 直接判断现有生成（口径不一致，过冲看不出来）；清洗占位符后重训（不是主要问题）；现在就试 9B（4B 的评估还没做对）。
- **回滚：** 见 [roadmap.md](roadmap.md) 4.4。

### ADR-024 P2 以 R0–R4 收尾后关闭

- **决定（Claude 2026-11-11 复盘提出，用户要求写入）：** P2 只再做 [roadmap.md](roadmap.md) 第 2 节"P2 收尾路线"中的 R0–R4，做完即关闭。之后不再新增修正实验，除非用户改范围。
- **两个提示词补充实验（R3）：**
  - **多轮角色格式：** 真人的历史发言放 assistant 位，客服发言放 user 位，任务目标放 system。其余与 `usersim/replay.py` 相同。这是唯一没试过的结构性做法。
  - **oracle 重做：** 目标反应的指令挪到 prompt 末尾并写得更明确。只作诊断，用来分清"做不到"还是"不知道什么时候该做"。
  - 每项先在 20 段上试，prompt 至多改一次；500 段正式实验只跑一次。不再试更多示例或长度控制。
- **理由：** P2 已经延长三次（v2、决策层、LoRA）。复盘发现"提示词修不动"的证据有两处设计偏弱（ADR-022 第 4 点），值得各补一次；再往下做，收益不抵范围膨胀（[roadmap.md](roadmap.md) 风险 5）。
- **放弃的替代方案：** 不补实验直接写稿（结论要打折）；持续迭代 prompt（没有终点）；用判断器做拒绝采样（只是把边际比例刷平，不提高 κ）。
- **止损与回滚：** 见 [roadmap.md](roadmap.md) 4.3、4.4。

## 项目结构

2026-10-28 的结构。数据集适配和指标是分开的，第一阶段换数据集或第二阶段换 WildChat 时，只需新增一个适配模块（ADR-005）。

```

  csds.py           CSDS 适配：读取、合并用户轮次（ADR-010）、摘要清洗（ADR-009/015）、抽样
  replay.py         逐轮重放的 prompt：只取第 t 轮之前的真实前缀，去分词空格（ADR-001/014）
  spark.py          模型客户端：provider=spark / sandbox（OpenAI 兼容）；并发、退避重试、10013 记为 moderated（ADR-012/013），逐请求记 token

  judge.py          Gemini 判断器（ADR-016）：话题走向 + 情绪表达；缓存、5xx 重试、输入指纹
  metrics.py        规则指标（关键词在 config/keywords.json）
  report.py         汇总表和 report.md
  anchors.py        修正方法：真实原话示例池与抽取（ADR-007，探索性）
  correction_v2.py  修正 v2：情境检索示例、轮次结构抽样
  correction_decision.py  决策层控制：目标反应抽样、oracle 诊断

  summary_overrides.json  逐段摘要清洗覆盖

  behaviors.json          行为规则
  judge_prompt.md         判断器定稿 prompt（哈希锁定于 outputs/judge_validation/final_prompt.json）

  measure_reaction_deepseek.py  DeepSeek 上的同一分组测量
```
