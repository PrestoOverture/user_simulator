# PRD：LLM 用户模拟器的真实性

> 来源：`misc/` 下 5 个输入文件。冲突时以 [项目总览](../misc/项目总览-用户模拟器真实性.md) 为准。

**标注约定（docs/ 全部文件通用）：**

- **待定**：需要你决定。

## 1. 一句话定义

测量**中文售后客服**场景中 LLM 模拟用户的失真形态，并提出低成本的修正方法。

## 2. 要解决的问题

- Agent 的评估和训练越来越依赖 LLM 扮演"用户"。
- 模拟用户在已知场景中系统性失真：过于配合、过于礼貌、话太长、不会放弃或升级。
- 结果：agent 的表现被高估。
- 中文客服场景的模拟器真实性尚未被测量（依据见 3.1 Qwen-DianJin 一行）。

## 3. 为什么值得做

结论：问题有价值、尚未解决、个人可以取得进展。

1. **不会被模型能力吸收。** 31 个模拟器上，更强的通用能力不带来更真实的模拟（Sim2Real Gap，**未核实**）。真实用户行为依赖特定人群和业务，模型本身没有这些信息。
2. **不被大厂资源垄断。** 大厂（如 Meta MIMESIS）做通用模拟器。约束是数据和洞察，不是算力。
3. **对企业有直接价值。** 部署对话 agent 的企业都需要可信的模拟器。
4. **符合问题驱动标准。**
5. **接近核心兴趣。** 模拟器是 agent 进化所处"世界"的一部分。

**评判标准（贯穿全项目）：** 以"问题是否有价值"为准，不以"有没有人做过"为准。可写进简历的成果必须包含一个**测量出来的、别人没注意到的发现**，不只是"搭了一个系统"。

### 3.1 核心依据文献

以下细节多来自 Gemini 报告转述，**全部未核实**。引用进论文或博客前须逐条核对原文。

| 工作 | 编号 | 在本项目中的作用 |

## 4. 三阶段研究问题

三个阶段共享**评估方法**，不共享结论（领域和语言都不同，不能直接叠加）。

| 阶段 | 维度 | 数据 | 研究问题 |
|---|---|---|---|
| 第一阶段 | 领域 | 中文售后客服 | 模拟器在具体业务里像不像真人 |
| 第二阶段·个体 | 个体 | WildChat 英文子集 | 在人群画像之外加入个人历史，会不会更像这个人 |
| 第二阶段·时间 | 时间 | WildChat 英文子集 | 同一用户随时间变化，模拟器能不能跟上 |

阶段顺序见 [architecture.md](architecture.md) ADR-008；数据见 [tech_stacks.md](tech_stacks.md) 第 4 节。

### 4.1 第一阶段的三个研究问题

1. **测量：** 中文售后客服中，模拟用户与真实用户的行为差距多大？差在哪些具体行为上？
2. **修正：** 能否用低成本方法缩小差距？方案见 [architecture.md](architecture.md) ADR-007。
3. **后果（放到后面）：** 失真让客服 agent 的评估被高估多少？需要搭建 agent，成本高。排期见 [roadmap.md](roadmap.md) D8。

### 4.2 核心结论与行为清单

**核心结论（2026-10-26 用户定）：** 客服回应之后的"反应方式"——真人往往就此结束这一话题，模拟器继续提出要求并把情绪说出来。定义、指标和判定规则见 [architecture.md](architecture.md) ADR-016。2026-10-26 分组测量按预先登记规则判定为**普遍定义**（不限定在被拒之后）；情绪表达的差距在被拒之后更大。表达层失真（话长、少短句、更礼貌）作为背景，是对 Sim2Real 结论的中文复现，不作为核心发现。

以下是试跑前的暂定清单，试跑后的取舍见 [试跑发现报告](../misc/试跑发现报告-2026-10-25.md) 和 [history.md](history.md)。

试跑后再定核心指标。试跑中的计算方法见 [任务规格 第 4 步](../misc/任务规格-试跑.md)。升级行为为何不含"要求转人工"见 [architecture.md](architecture.md) ADR-011。

| 层级 | 行为 | 预期失真的依据（均**未核实**） |
|---|---|---|
| 决策层 | 升级要求（主管、投诉、差评、12315） | 模拟器倾向配合 |
| | 拒绝方案 | 婚恋销售研究：模拟器的抗拒程度减半 |
| | 未解决就离开（需自由对话模拟） | 同一研究：模拟用户不会离开 |
| 施压层 | 重复追问 | 模拟器倾向接受回答、推进对话 |
| | 催促 | 缺少真实的不耐烦 |
| 表达层 | 短句率 | Sim2Real：真人 29% 是简短话语，模拟器约 1% |
| | 信息披露方式（首轮倾倒 vs 逐步给出） | Sim2Real：模拟器首轮倾倒信息 |
| | 礼貌程度 | Sim2Real：模拟器礼貌程度约为真人 3 倍 |
| | 自我更正 | MobileCS 有 Turnback 标注 |

**选择核心指标的两个条件：**
1. 在真实数据中足够常见；
2. 真人与模拟器差距明显。

预想候选：升级要求、拒绝方案（决策层）；短句率、信息披露方式（表达层）。以试跑结果为准。

## 5. 范围

### 5.1 范围内

- 第一阶段：测量 + 修正。
- 第二阶段：个体维度 → 时间维度。前提是你决定进入（[roadmap.md](roadmap.md) D7）。
- 可复用的评估管线（[architecture.md](architecture.md) ADR-005）。
- 副任务：AIDev 伪影核实（[roadmap.md](roadmap.md) 第 6 节）。

### 5.2 范围外

- 第一阶段内的"后果"研究（agent 被高估多少）。放到后面，防止范围膨胀。
- 训练或微调大模型；招募真人；涉及未成年人；心理危机干预等高风险场景（研究提案 6.3）。
- Gemini 报告推荐的其他场景（议价、语音客服、技术排障、医疗、金融）。输入文件未将它们纳入本项目。

### 5.3 已放弃的方向

决策链已定，不再讨论。来源：项目总览第 2 节。

| 方向 | 结论 | 理由 |
|---|---|---|
| Octonoesis 继续做 coding agent | 放弃 | coding agent 在简历上已没有区分度 |
| Personal agent | 放弃 | 入口被大厂生态控制，个人在 harness 层难以建立壁垒 |
| 用文本 skill 实现自进化 | 放弃 | 文本 skill 会被模型能力吸收（Violoop 也去掉了 skill 层） |
| 结构涌现（触手的分裂/合并） | 暂缓 | 有兴趣，但落在文本层，同样面临被吸收的风险 |
| 岗位模型（蒸馏许多员工） | 放弃 | 没有公开的岗位数据 |
| 个人工作分身（用自己的数据） | 放弃 | n=1，无法验证方法 |
| 个人审查分身（GitHub / AIDev） | 放弃 | 实测个人效应远小于仓库效应；纯跨仓库迁移的预测增益接近 0；对仓库/PR 类题目没有兴趣 |

AIDev 方向的原始交接见 [handoff-ai-review-twin_1.md](../misc/handoff-ai-review-twin_1.md)。

## 6. 成功标准：第一阶段

**终点：** 一份测量报告（哪些行为失真、失真多少）+ 一个低成本修正方法及其效果。

**产出形式：** 技术博客或 arXiv 短文（[roadmap.md](roadmap.md) D6）。

**硬要求：** 成果能独立写进简历，不依赖后面的阶段。

**简历叙事模板：** "首次测量了中文售后客服场景中 LLM 用户模拟器的系统性失真，发现 X；提出基于真实原话的免训练修正方法，将 Y 指标的差距缩小了 Z。"

X、Y、Z 由实验决定。修正效果达到多少算"成功"：**待定**（输入文件未给出阈值）。

## 附：冲突与差异

1. **研究问题的顺序。** 研究提案第 4 节为"测量 → 后果 → 修正"。项目总览为"测量 → 修正 → 后果（放到后面）"。以项目总览为准。
2. **第一阶段的数据。** 研究提案第 5 节以 JDDC 为主数据。项目总览以 CSDS 为主，JDDC 仅备用。以项目总览为准。
3. **主线选择。** Gemini 报告（第 4、5.3 节）建议以"跨会话长期演化"为论文主线，中文售后客服为第二实验域。项目总览定为第一阶段做中文售后客服，跨会话放在第二阶段。以项目总览为准。
