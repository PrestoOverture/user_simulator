## 4. 终止 / 暂停条件

### 4.1 试跑停止条件（任务规格第 3 节）

遇到时停下并报告，不要自行绕过。

| 条件 | 停下后的可选项（由你选） |
|---|---|
| CSDS 无法下载，或格式与预期差别很大 | 改用 MobileCS 或 ECD；申请 JDDC；调整试跑设计以适配实际格式 |
| Spark API 无法调用 | 等待 / 联系讯飞解决；改用其他模型做模拟器（违反 ADR-006 的试跑约束，须你明确批准） |

2026-10-25 用户调整：不再检查 Spark 使用条款；取消 token 上限。

### 4.2 试跑后没有任何指标同时满足两个条件

只列选项，不做选择：

1. **修正规则后重算。** 关键词误判可能掩盖差距（风险 3）。根据 `report.md` 第 5 问修改关键词，再算一遍。
2. **扩大试跑样本。** 20 段可能不足以让罕见行为出现。
3. **换或加数据集。** 例如 MobileCS（有 Turnback 标注）或 ECD。
4. **提前做自由对话模拟。** "未解决就离开"等整段行为在逐轮重放中测不到。
5. **用模型判断代替关键词。** 需先定 D5。
6. **放宽条件。** 例如只满足"差距明显"的指标也纳入，并在报告中写明其罕见。
7. **暂停，重新评估第一阶段场景。**

## 6. 副任务 S1：AIDev 伪影核实

**独立、低优先级。** 不阻塞主线。来源：项目总览第 8 节。

- **待核实的说法（未核实）：** GitHub 会把 PR 作者回复审查评论自动记录为一条 COMMENTED 状态的审查。这类记录约占人类审查事件的 24.8%，会把审查者个人效应（ICC）从约 22.9% 虚高到约 35.3%。至少一篇已发表的 AIDev 论文没有处理这个问题。
- **出处：** Antigravity 的 AIDev 测量报告。该报告不在本次 5 个输入文件中。
- **核实方法：** 随机挑几个 AIDev 中的 PR，到 GitHub 上看作者回复评论时是否真的生成了审查记录。
- **意义：** 若属实，本身就是一个"别人没发现、你发现了"的成果。
- **附带更正：** 那份报告对"两人实质裁决 97.48% 一致"的解读有误。基础比率约 90% 都是批准，κ 只有 0.266；只要有一人驳回，另一人有 84% 的情况不同意。说明大家在"什么该驳回"上分歧很大。
- **数据背景：** 见 [handoff-ai-review-twin_1.md](../misc/handoff-ai-review-twin_1.md)。
- **何时做：** **待定**（项目总览："有空时"）。
