# Handoff — 个人对 AI 产出的判断：个体差异是否值得建模

## Context

David 在为 Octonoesis 寻找新方向（不再做 coding agent）。经过多轮收敛，方向落在"工作分身"：从一个开发者的历史记录中，学到他对 AI 产出的判断。本次交接的任务是**一个前置测量，而不是建模**：在公开数据中，开发者对 AI 产出的审查判断，有多少差异是由**个人**解释的，而不是由**仓库/团队规范**解释的。这个结果决定整个方向是否值得继续。

## Decisions（已定，不需要重新讨论）

- **进化落在记忆或权重，不落在文本 skill。** 理由：通用的文本 skill 会随模型升级被吸收（参考：Violoop 曾走"长期记忆 → skill → 参数"，后来去掉了 skill）。
- **目标是工作分身，不是观点分身。** 观点分身有公开数据（Twin-2K-500、HugAgent），但与目标岗位（agent 工程）关系弱。
- **必须用多个体的公开数据。** David 自己的数据是 n=1，无法验证方法。
- **数据必须反映当前的 AI 编程方式。** 2022 年以前的代码审查数据（GH Archive、Gerrit）已被否决：工作方式和现在差别太大。
- **训练目标是人的判断，不是 AI 的输出。** AI 写的代码是判断的**对象**，人对它的反应（接受、驳回、要求修改、理由）才是信号。这样处理了"用 AI 数据训练 AI"的顾虑。
- **候选数据集：AIDev。** 932,791 个 agent 发起的 PR（Codex、Devin、Copilot、Cursor、Claude Code），116,211 个仓库，72,189 名开发者，截止 2025-08-01。Hugging Face：`hao-li/AIDev`；GitHub：`SAILResearch/AI_Teammates_in_SE3`；论文 arXiv 2507.15003、2602.09185。

## Open Questions

1. **核心问题：** 控制仓库和 PR 特征以后，审查判断中由**审查者个人**解释的方差有多大？
2. 每名人类审查者有多少条记录？有足够记录的审查者有多少？
3. 同一审查者跨仓库时，判断倾向是否一致？（如果一致，说明是"个人"而不是"仓库"）
4. 是否已有工作对个人（而非群体或团队）在 AI 产出上的判断建模？AIDev 已有 70+ 篇引用论文，目前只粗看了标题，似乎都是群体层面的研究。

## Next Steps（按优先级）

1. **数据审计**
   - 下载 AIDev，列出所有表及字段，确认审查表在全量还是只在 AIDev-pop 中。
   - 过滤 bot：账号名带 `[bot]` 后缀，以及明显的自动化账号。
   - 统计每名人类审查者的审查条数分布（中位数、P90、≥20 / ≥50 / ≥100 条的人数）。
   - 统计有 ≥2 名活跃审查者的仓库数量（做"仓库内对比"所需）。
2. **方差分解（核心测量）**
   - 结局变量：审查结论（APPROVED / CHANGES_REQUESTED / COMMENTED），以及 PR 最终是否合并。
   - 模型：混合效应 logistic 回归，`结论 ~ PR 特征（agent 类型、改动行数、文件数、任务类型） + (1|仓库) + (1|审查者)`。报告仓库和审查者各自的 ICC（组内相关系数）。
   - **混杂因素必须说明：** 审查者被分配到的 PR 不是随机的。要控制 PR 特征；能做"同一仓库、同类 PR、不同审查者"的对比更好。
3. **意见内容的个体差异（次要）**
   - 给行内审查意见打类别（如：正确性、测试、风格、命名、架构、安全；可以先用 LLM 分类，再人工抽查准确率）。
   - 检验：控制仓库后，不同审查者的意见类别分布是否显著不同（卡方检验或互信息）。
4. **文献核查**
   - 浏览 AIDev 引用论文列表（Hugging Face 数据集页面有清单），确认没有人做过个人层面的判断建模。
   - 检索"reviewer-specific / personalized code review model"相关工作。已知的个性化工作方向是"让审查说明适应读者"（arXiv 2607.08990），不是"模仿审查者"。
5. **输出结论报告**，包含：数据规模表、方差分解结果、个体差异的证据强弱、文献核查结果、以及"继续 / 停止"的建议和理由。

## 决策标准（暂定，由 David 最终决定）

- **个人效应很小**（审查者 ICC 远小于仓库 ICC，且跨仓库不一致）→ 应用退化为团队级奖励模型（已有企业在做，如 Atlassian 的审查意见排序器），分身方向停止。
- **个人效应显著**（控制仓库后仍有明显个人差异，且跨仓库稳定）→ 进入建模阶段：个人模型 vs 团队模型 vs 通用模型。
- **数据量不足**（活跃审查者太少）→ 结论是"无法判断"，报告具体缺口，不要强行得出结论。

## 背景：如果方向成立，它的用途

同一个模型（"这个人会怎样判断这份 AI 产出"）有三种用途：预先筛选 agent 产出以节省审查时间；作为奖励模型做 agentic RL；作为 agent 自主度的依据（有把握通过时自己合并，没把握时才找人）。参考数据：agent PR 接受率明显低于人类（Codex 64%、Devin 49%、Copilot 35%，人类基线 76.8%），人的审查是瓶颈。
