## 1. 一句话定义

Agent 的评估和训练越来越依赖 LLM 扮演"用户"。这些模拟用户在已知场景中系统性失真：过于配合、过于礼貌、话太长、不会放弃或升级，导致 agent 的表现被高估。本项目测量**中文售后客服**场景中模拟用户的失真形态，并提出低成本的修正方法。

## 2. 为什么是这个方向（决策链，已定，不需要重新讨论）

这个方向是经过多轮筛选得出的。每一步的取舍如下：

| 被考虑的方向 | 结论 | 理由 |
|---|---|---|
| Octonoesis 继续做 coding agent | 放弃 | coding agent 在简历上已没有区分度 |
| Personal agent | 放弃 | 入口被大厂生态控制，个人在 harness 层难以建立壁垒 |
| 用文本 skill 实现自进化 | 放弃 | 文本 skill 会被模型能力吸收（Violoop 也去掉了 skill 层） |
| 结构涌现（触手的分裂/合并） | 暂缓 | 有兴趣，但落在文本层，同样面临被吸收的风险 |
| 岗位模型（蒸馏许多员工） | 放弃 | 没有公开的岗位数据 |
| 个人工作分身（用自己的数据） | 放弃 | n=1，无法验证方法 |
| 个人审查分身（GitHub / AIDev） | 放弃 | 实测个人效应远小于仓库效应；纯跨仓库迁移的预测增益接近 0；另外对仓库/PR 类题目没有兴趣 |
| **用户模拟器（数字分身作为环境）** | **采用** | 见下 |

**采用的理由：**

1. **不会被模型能力吸收。** 已有研究在 31 个模拟器上发现，更强的通用能力并不带来更真实的用户模拟（Sim2Real Gap, arXiv 2603.11245）。模拟真实用户需要的是特定人群、特定业务的行为信息，而这些信息模型本身没有。
2. **不被大厂资源垄断。** 大厂（如 Meta 的 MIMESIS）在做通用模拟器；而具体业务的真实用户行为数据分散在各处。约束是数据和洞察，不是算力。
3. **对企业有直接价值。** 所有部署对话 agent 的企业，都需要可信的模拟器来评估和训练。
4. **符合"问题驱动"的标准。** 问题有价值、尚未解决、个人可以取得进展。
5. **接近你的核心兴趣。** 模拟器是 agent 进化所处"世界"的一部分。

**评判标准（贯穿全项目）：** 不以"有没有人做过"为标准，而以"问题是否有价值"为标准。需要重新造一部分轮子是正常的。但可写进简历的成果，必须包含一个**测量出来的、别人没注意到的发现**，而不只是"搭了一个系统"。

## 3. 三阶段路线

```
第一阶段：中文售后客服      → 领域维度：模拟器在具体业务里像不像真人
第二阶段：WildChat 多会话   → 个体维度：在人群画像之外加入个人历史，会不会更像这个人
                            → 时间维度：同一个用户随时间的变化，模拟器能不能跟上
```

- 第二阶段合并了原来的"跨会话演化"和"个人历史"两个问题，因为它们用同一份数据、同一套管线。**先做个体维度**（一个简单的 A/B 对比），再做时间维度。
- 第一阶段（中文任务型对话）和第二阶段（英文通用聊天）的领域和语言都不同，结论不能直接叠加。三个阶段共享的是**评估方法**，所以从第一天起就要把评估管线写成可复用的。
- 第二阶段**只用 WildChat 英文子集**。WildChat 收集期间，中国大陆用户访问 ChatGPT 大多通过代理或 VPN，共享出口 IP 很常见，用 hashed_ip 串联"同一用户"在中文子集上不可靠。英文子集也有 IP 变化带来的噪声，需要按 Gemini 报告的建议清洗（只用 2024 年 9 月之前的数据，hashed_ip 和 header 必须一致，剔除模板化流量）。

## 4. 第一阶段的研究设计

### 4.1 研究问题

1. **测量：** 在中文售后客服中，LLM 模拟用户与真实用户的行为差距有多大？差在哪些具体行为上？
2. **修正：** 能否用低成本方法缩小差距？首选方案：用同类真实用户的**原话片段**约束模拟器。依据：RealUserSim 的消融实验显示，去掉原话示例会让保真度下降约 8 个百分点，而去掉人口统计标签几乎没有影响（以 Gemini 报告的转述为准，需要核实原文）。
3. **后果（放到后面）：** 失真会让客服 agent 的评估被高估多少？这需要搭建 agent，成本较高。

### 4.2 已定的方法决策

- **逐轮重放为主。** 保持真实对话前 t−1 轮不变（包括真实客服的发言），只让模拟器生成第 t 轮。这样客服一侧完全相同，差异只来自模拟器。原因：真实日志中用户面对的是人工客服，如果让模拟器和我们的 agent 自由对话，差异就无法归因。
- **自由对话模拟作为补充。** 只用于"未解决就离开"这类整段对话层面的行为，放在第一阶段后半段。
- **配对比较为主，整体分布比较为辅。** 配对比较指：同一个上下文下，真人做了某个行为，模拟器有没有做。
- **能用规则就用规则。** 需要模型判断的行为，判断模型不能和模拟器是同一个（避免偏向自己的输出风格），并人工抽查约 50 条确认准确率。
- **多模型对比。** Spark 2.6 作为主力（有 10 亿 token 免费额度）；另用一两个低价模型做小样本对比，确认发现不是 Spark 特有的。GPU 成本允许的话，加入开源的 MIMESIS-4B/9B 作为参照。

### 4.3 关键的数据限制

CSDS、MobileCS、ECD 中的用户面对的都是**人工客服**，所以"要求转人工"这个行为在这些数据里不存在。要用人工客服场景中对应的升级行为代替：要求主管、威胁投诉或差评、重复追问、未解决就离开。

### 4.4 暂定的行为清单（试跑后再定核心指标）

| 层级 | 行为 | 预期失真的依据 |
|---|---|---|
| 决策层 | 升级要求（主管、投诉、差评、12315） | 模拟器倾向配合 |
| | 拒绝方案 | 婚恋销售研究：模拟器的抗拒程度减半 |
| | 未解决就离开（需要自由对话模拟） | 同一研究的核心发现：模拟用户不会离开 |
| 施压层 | 重复追问 | 模拟器倾向接受回答、推进对话 |
| | 催促 | 缺少真实的不耐烦 |
| 表达层 | 短句率 | Sim2Real：真人 29% 是简短话语，模拟器约 1% |
| | 信息披露方式（首轮倾倒 vs 逐步给出） | Sim2Real：模拟器首轮倾倒信息 |
| | 礼貌程度 | Sim2Real：模拟器礼貌程度约为真人 3 倍 |
| | 自我更正 | MobileCS 有 Turnback 标注 |

**选择核心指标的两个条件：**（1）在真实数据中足够常见；（2）真人与模拟器差距明显。预想的核心候选是"升级要求""拒绝方案"（决策层）加上"短句率""信息披露方式"（表达层），但以试跑结果为准。

## 7. 第一阶段的终点与产出

- **试跑（下一步）：** 见 `任务规格-试跑.md`。20 段对话、逐轮重放、规则统计、token 用量推算。
- **正式实验：** 根据试跑结果确定核心指标，扩大样本，加入多模型对比。
- **修正方法：** 原话片段约束，与无约束基线对比。
- **结束标志：** 一份测量报告（哪些行为失真、失真多少）加一个低成本修正方法及其效果，整理成技术博客或 arXiv 短文。**这个成果要能独立写进简历，不依赖后面的阶段。**
- **简历叙事方向：** "首次测量了中文售后客服场景中 LLM 用户模拟器的系统性失真，发现 X；提出基于真实原话的免训练修正方法，将 Y 指标的差距缩小了 Z。"

## 8. 副产品：AIDev 数据中的方法学问题（值得单独处理）

Antigravity 在 AIDev 测量中报告了一个发现：GitHub 会把 PR 作者回复审查评论自动记录为一条 COMMENTED 状态的审查。这类记录约占人类审查事件的 24.8%，会把审查者个人效应（ICC）从约 22.9% 虚高到约 35.3%。报告还称，至少一篇已发表的 AIDev 论文没有处理这个问题。

**如果核实属实，这本身就是一个"别人没发现、你发现了"的成果。** 核实方法：随机挑几个 AIDev 中的 PR，到 GitHub 上看作者回复评论时是否真的生成了审查记录。

同时注意：那份报告对"两人实质裁决 97.48% 一致"的解读有误。基础比率约 90% 都是批准，κ 只有 0.266；只要有一人驳回，另一人有 84% 的情况不同意。所以它其实说明了大家在"什么该驳回"上分歧很大。

## 9. 风险与注意事项

1. **数据较早，且用户面对的是人工客服。** 用户面对 AI 客服时可能更没耐心。缓解：用 WildChat 中文部分（真实用户面对 AI）做交叉对照，并在论文中把它写成局限。
2. **只用 Spark 的结论没有普遍性。** 必须加入其他模型的小样本对比。
3. **关键词规则会误判。** 试跑时人工抽查，正式实验中对关键行为使用经过验证的分类器。
4. **Spark 免费额度的条款。** 有效期、速率限制、是否允许研究用途，需要在试跑第 0 步确认。
5. **不要让范围膨胀。** 第一阶段先做测量和修正；"后果"（agent 被高估多少）放到后面。
