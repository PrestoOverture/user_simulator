# Research Proposal：LLM 用户模拟器的真实性缺口——寻找未被测量的领域

## 1. 一句话概述

Agent 的评估和训练越来越依赖 LLM 扮演的"用户"。这些模拟用户在已测量的场景中系统性地失真（过于配合、不会放弃），从而让 agent 的表现虚高。本提案要找到**还没有被测量过、但有商业价值的场景**，在那里第一个测出失真的形态，并提出修正方法。

本文档有两个用途：
1. 记录已确定的研究方向和第一个候选场景（中文电商客服）。
2. **交给研究 agent 的任务（第 6 节）：找出除中文电商客服以外，还有哪些"蓝海"场景。**

## 2. 动机：为什么是这个问题

研究者的核心兴趣是"让 agent 进化的世界"。用户模拟器就是 agent 所处世界的一部分：模拟器失真，agent 就会在一个错误的世界里进化，学到的东西在真实世界失效。

这个方向满足三个条件：
- **不会被模型能力吸收。** 已有研究在 31 个模拟器上发现，更强的通用能力并不带来更真实的模拟。模拟真实用户需要的是**特定人群、特定业务的行为信息**，而这些信息模型本身没有。
- **不受大厂资源垄断。** 大厂在做通用模拟器；而每个行业、每个人群的真实用户数据分散在各处，约束是数据和洞察，不是算力。
- **对企业有直接价值。** 所有部署对话 agent 的企业，都需要可信的模拟器来评估和训练。

## 3. 已知事实（研究 agent 需要核实标注了 ⚠️ 的条目）

| 工作 | 编号 | 关键发现 |
|---|---|---|
| Mind the Sim2Real Gap | arXiv 2603.11245 | 451 名真人完整跑 τ-bench。LLM 模拟用户过于配合、风格单一、缺少挫败感，导致 agent 成功率虚高；31 个模拟器中，通用能力更强不等于模拟更真实 |
| Lost in Simulation | arXiv 2601.17087（ACL 2026） | 不同模拟器之间 agent 成功率相差可达 9 个百分点；对 AAVE 和印度英语使用者效果最差 |
| RealUserSim（Salesforce） | arXiv 2605.20204 | 从 WildChat 提取 7,275 个真实行为画像来约束模拟器，匹配率从 24.2% 提高到 45.3% |
| MIMESIS（Meta）⚠️ | 仅见新闻报道 | 训练专用 9B 模拟器；同一 agent 面对真人成功率 63.6%，面对前沿模型扮演的用户为 82.4%–84.4% |
| Simulated Customers Never Walk Away | arXiv 2606.20708 | 中国婚恋服务的真实销售对话（2,790 条，793 条确认付款）。模拟器把最终不购买的客户模拟得过于投入：抗拒减半（25.1%→13.5%），犹豫翻倍（21.9%→40.1%）。提出 decision fidelity 概念 |
| Real or Robotic? | arXiv 2409.08330 | 在 WildChat 上比较英、中、俄三种语言的模拟器；中文在词汇和语义上较好，在对话结束方式上较差 |
| Twin-2K-500 / Funhouse Mirrors | arXiv 2505.17479 / 2509.19088 | 个人数字分身在留出问题上准确率较高，但在全新情境下基本无法忠实模仿真人 |
| HugAgent（MIT） | arXiv 2510.15144 | 模型能较好还原一个人当前的信念，但难以预测他在干预后的信念更新 |

**已形成的规律：** 每一次有人在新场景中第一次认真测量，都会发现一种之前没人注意到的失真形态（过于配合、不会放弃、风格单一、对特定人群失效）。这就是本方向"出发现"的机制。

## 4. 通用研究问题

在场景 X 中：
1. **测量：** LLM 模拟用户与真实用户的行为差距有多大？差在哪些具体行为上？（特别是"不配合"的行为：拒绝、放弃、升级情绪、模糊表达、重复追问）
2. **后果：** 用这样的模拟器评估或训练 agent，会让 agent 的表现被高估多少？
3. **修正：** 能否用低成本方法（例如用真实数据提取的行为画像约束模拟器）缩小这个差距？

## 5. 候选场景 1：中文电商客服（已初步评估）

- **数据：** JDDC（京东客服真实对话，100 万+ 多轮对话，2,000 万条话语）；WildChat 中文部分（真实用户对 AI，约占 13% 的轮次）。
- **假设：** 模拟用户系统性地低估客服场景的典型"不配合"行为：要求转人工、情绪升级、重复追问、只发半句话、问题没解决就离开。
- **空白：** 就目前检索范围，中文客服场景的模拟器真实性尚未被测量。婚恋销售（2606.20708）是最接近的前作，但它是销售场景，不是服务场景。
- **风险：** JDDC 的用户面对的是人工客服，且数据较早（2020 年发表）；用户面对 AI 客服时的行为可能不同。JDDC 的获取方式（是否需要申请）尚未确认。

## 6. 交给研究 agent 的任务：寻找其他蓝海场景

### 6.1 "蓝海"的判断标准（全部需要满足，或说明哪一条不满足）

1. **有商业需求：** 这个场景里已经或正在大规模部署对话 agent。
2. **需要模拟器：** 这个场景的 agent 评估或训练，需要或已经在使用模拟用户。
3. **尚未被测量：** 检索不到针对这个场景的模拟器真实性测量（要给出检索过程和结果，不能只说"没找到"）。
4. **有公开的真实用户数据：** 可以免费获得，许可证允许研究使用。
5. **低成本可行：** 只用 API 调用即可完成测量，不需要训练大模型，不需要招募真人。
6. **预期有独特的失真形态：** 能说出这个场景里真实用户的哪种行为，模拟器很可能模仿不好，以及理由。

### 6.2 建议探索的维度（不限于此）

- **业务领域：** 银行和金融客服、医疗问诊和挂号、政务服务热线、教育辅导、旅行预订、游戏玩家（NPC 交互）、售后维修。
- **人群：** 老年用户、方言使用者、非母语使用者、低数字素养用户。
- **模态：** 语音（打断、停顿、口语化），对比文字。
- **行为类型：** 决策行为（买不买、续不续费）、情绪行为、放弃行为。
- **时间维度：** 同一个用户在多次会话中的变化（长期用户的模拟是否随时间失真）。这个维度和研究者的长期兴趣最相关，请重点检索。

### 6.3 明确排除

- 需要训练或微调大模型的方案。
- 需要自行招募真人、收集新数据的方案。
- 涉及未成年人的场景。
- 心理危机干预等高风险场景（伦理成本过高）。

### 6.4 交付物

1. **候选场景表：** 每个场景按 6.1 的六条标准逐条评估，附数据集链接、许可证、前作链接。
2. **前作检索记录：** 对每个候选场景，列出用过的检索词和找到的最接近的工作，说明它为什么没有覆盖这个场景。
3. **对候选场景 1 的核实：** 再检索一次中文客服场景的模拟器真实性研究，确认第 5 节的"空白"判断是否成立；确认 JDDC 的获取方式。
4. **核实第 3 节标注 ⚠️ 的条目**，找到 MIMESIS 的原始论文或官方发布。
5. **推荐 Top 3：** 按"发现的可能性 × 商业价值 × 可行性"排序，每个给出一段理由和最大风险。
