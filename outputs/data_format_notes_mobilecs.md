## 规格第1步：五个问题

1. **结构与说话人**：UTF-8 JSON 顶层 list，10 个对象，每个仅有 `id`（字符串）和 `content`（turn 对象列表）。98 个 turn 均含 `[SPEAKER 1]`、`[SPEAKER 2]`、`客服意图`、`用户意图`、`info`。样例中 SPEAKER 1 是客服、SPEAKER 2 是用户；同一 turn 包含两个发言，不是单条消息。前9段键顺序客服→用户，最后1段用户→客服，因此不能一律按数字排序展开。JSON 对象的键顺序仅是发布序列化的线索，正式适配仍需确认话语顺序约定。
2. **用户连发分开还是合并**：每个 turn 每位说话人只有一个字符串；没有聊天消息列表、时间戳或连发条数。可见文本保留口语重复、停顿 `_` 与 `[UNK]`。在这个表示层面是一段说话人文本；无法从样例确认原始通话切分时是否把多个片段合并，更不能恢复聊天连发次数。不能把 `_` 当消息分隔符。
3. **用户诉求摘要及结果**：没有 `UserSumm` 或其他人工自然语言用户摘要。`用户意图` 是逐轮标签，不是整段诉求摘要；`info` 是实体/属性。Track2 README 说明 user goal/local KB 还需抽取。文本本身含业务结果（如样例1客服说短信已下发），从全对话抽取目标可能泄露结果；本任务不抽取、不自行决定目标替代规则。
4. **问题是否解决**：10段样例中无独立 solved/success/解决标注。意图“取消”“再见”等不能直接映射为解决。Track2 文档提到的生成系统 Success rate 和人工评分是评测指标，不是当前样例自带的解决标签；受限全量是否另有字段未验证。
5. **总量与平均轮数**：本地样例10段、98个成对 turn，平均9.8个成对 turn/段；按单人发言计196条、19.6条/段；用户发言98条、9.8条/段。各段turn数依次8、13、8、10、8、14、9、9、9、10。官方 data README 宣称约100,000段（10K标注、90K无标注），另留约1K评估；未下载全量，无法实测其平均轮数、确切总量或大小，不能外推样例均值。

## Turnback 与特殊标注

**“MobileCS 含 Turnback 标注”未核实成立。** 已检查公开 README、两赛道 README 与样例：没有名为 Turnback/turnback/改口 的字段或格式说明。不能给出不存在于证据中的标注格式，也不能断言受限全量一定没有。另有同一 SereTOD workshop 的独立论文 [Oh My Mistake!](https://aclanthology.org/2022.seretod-1.1/) 研究模板注入的 turnback；不能据共同会议归属推定 MobileCS 有此标注。

实际特殊标注：`用户意图`、`客服意图` 为字符串，可以逗号连接多个意图，用户求助还可含括号实体/属性，例如 `问候,求助-查询（ent-1-流量范围）`。`info.ents[]` 包含 `name/id/type/pos`，pos 可为多组 `[话语序号,起点,终点]`；`info.triples[]` 包含 `ent-id/ent-name/prop/value/pos`，pos 为一组三元组。样例1 `半年` 的 pos 是 `[2,15,17]`，与第2个话语字符串的 Python 切片 `[15:17]` 对应，支持零起点、右端不含的解释；序号不是稳定的角色编号（最后一段用户先出现）。缺失关联可用字符串 `NA`。`_`、`[UNK]` 原样保留，不认作改口标签。

## usersim 适配层：只读检查与字段映射

核对当前 `usersim/csds.py` 的 `load/user_turns/sample/clean_summary` 与 `usersim/replay.py` 的 `prompt`；没有通用注册式接口。**不能把原文件直接传给现有 CSDS 适配函数。** `load` 仅扫描顶层 *.json 并添加 split；其余函数直接索引 CSDS 字段。

| MobileCS 字段 | 现接口所需字段 | 映射与缺口 |
|---|---|---|
| `id` | `DialogueID` | 可直接保留字符串 |
| 来源文件/公开样例身份 | `split` | 需显式记录 example，不能假冒 train |
| `content` 每轮两个说话人字符串 | `Dialogue[]` | 需先确认并保留每轮实际话语顺序，再展开两条消息 |
| `[SPEAKER 2]` | `speaker='Q'` | 公开样例用户角色；全量仍须验证 |
| `[SPEAKER 1]` | `speaker='A'` | 公开样例客服角色 |
| 字符串原文 | `utterance` | 保留 `_`、停顿、未知词，不清洗 |
| 用户角色 | `QRole='用户'` | 由已确认角色设置，供 sample 过滤 |
| 无 | `UserSumm: list[str]` | 核心缺口，不从未来轮次/结果自动制造；交 Claude 决定目标来源 |
| 意图、info | 当前接口无对应输入 | 保留源数据；不可当成摘要或 solved |

`user_turns` 依赖连续 Q 消息生成 `start/messages`；MobileCS 不能恢复聊天连发条数。现有 replay.SYSTEM 固定为京东购物售后角色，与移动通信场景不匹配，不能直接复用实验语义。本任务只记录映射，不改 usersim，不运行 replay，也不作目标抽取或实验设计决定。
